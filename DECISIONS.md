## Product & scope
- **D-01 (2026-08): App renamed WayReally → Observatory.** Xcode project, entitlements paths, and docs all migrated; stray `second/` paths fixed (`ad29322`, `bdf515c`).
- **D-02 (2026-10): The product is about expression, not just words.** Prolonged sounds, compressed/accelerated delivery, reduced articulation, and change in expression are the signal; words are context. Stretching may *accompany* uncertainty but never *establishes* an emotion.
- **D-03: Observation / interpretation / self-report are three distinct, separately-persisted layers.** Nothing infers felt emotion from deliberate test speech; nothing asserts an emotion from a single acoustic cue. Interpretations are tentative, non-exclusive (`alternativeExplanations`), and support user correction.
- **D-04: No external audio/ML services; recordings stay on-device — now code-enforced** (2026-10-21, uncommitted): `requiresOnDeviceRecognition = true` in `SpeechRecognitionManager.swift`. Known consequence: Apple's on-device recognizer loses fidelity on quiet/multi-speaker audio (measured: 9–19% word recovery vs 70%+ server-side; prime suspect is capture gain — `.measurement` mode disables system AGC). Whether to add an explicit opt-in server-based mode with its own consent flow is an open **user/product decision** (PLAN.md U2), not an agent decision.

## Speech pipeline (Stage 0, implemented 2026-10-15)
- **D-05: Frame accounting counts successful writes only.** `capturedFrames` / `enqueuedFrames` / `writtenFrames` are distinct; downstream offset math uses `writtenFrames` and a per-recording fixed sample rate (piecewise segments if the rate ever changes mid-recording).
- **D-06: Generation-tagged recognition lifecycle.** Monotonic `requestGeneration`, single-rollover guard, rapid-restart guard, lock-unified `endAndClear` (closes the append/endAudio race). Audio engine is never stopped/restarted at segment boundaries — only the recognition request is swapped (`CurrentRequestBox`).
- **D-07: `nil` means unavailable, never `0`.** Optional word `audioStart/audioEnd` with backward-compatible legacy decode; unavailable features are marked unavailable, not defaulted to neutral values.
- **D-08: Typed diarization results.** `DiarizationResult.segments` replaced RTTM text parsing; word-level speaker matching by overlap duration; honest `Speaker.overlap/.unknown` instead of defaulting to `.user`; raw segments + filtering decisions persisted for audit.
- **D-09: Reliability gates analysis.** `audioRecordingReliable == false` or `missingAudioIntervals` gates BOTH diarization and (future) acoustic-feature extraction; `stop()` awaits writer drain before anything opens the file.
- **D-10: Fixture validation method.** The three saved fixtures (`fixture-solo.caf`, `fixture-multi-a.caf`, `fixture-multi-b.caf`) are read-only baselines. Re-diarizing saved session JSON cannot validate Stage 0 (original timing was already discarded) — validation re-transcribes each `.caf` through a test-only replay harness sharing the live code path (`SpeechTranscriptTimingMapper`), then diarizes that output.
- **D-11: Speaker labels never guess identity.** Diarization ("who spoke when") is separate from identification ("is this Chris?"); labels stay "Speaker 1/2/3" without enrollment or explicit user confirmation (constraints §8).
- **D-12: SpeakerKit pinned to 1.0.0** (Pyannote v4 on-device).

- **D-15: Plans get independent review before execution.** STABILIZATION_AND_EXPRESSION_PLAN.md went through two ChatGPT review revisions before approval; the same applies to future multi-file plans.
- **D-16: Thresholds are data, not Swift constants.** Acoustic/detection thresholds go through the SignalLibrary rule pattern (`SignalRuleMatchType` numeric case), per constraints §7. Hard-coded rules are temporary prototypes requiring a documented migration path.
- **D-17 (2026-10-23): Capture completeness is its own signal (ChatGPT brief #4 ruling: modified Option B).** `ReflectionSession.captureCompleteness: CaptureCompleteness?` (`.complete` / `.incomplete(endpointAudioSeconds:)` / `nil`=unknown-legacy, never decoded as complete) records whole-session capture completeness, established ONLY from lifecycle evidence (`hadCaptureOutage`, set at interruption `.began`, never cleared by a later successful recovery). `endpointAudioSeconds` marks solely where the saved file ends — not "known-good through here," not when capture stopped, not the missing duration. `audioRecordingReliable`/`missingAudioIntervals` keep their exact write-integrity meaning (no boolean overload — Option A rejected; no fabricated/zero-duration `AudioInterval`s — Option C rejected, per the Q3 precedent). `SpeakerDiarizationEngine.label(session:)` skips confirmed-incomplete sessions in the same change; analysis engines respecting completeness is U3 scope.
- **D-18 (2026-10-24): Incomplete sessions get coverage-scoped analysis, not blanket exclusion.** Owner decision grounded in the product's SaMD-grade measurement direction (PLAN.md project one-liner). When `captureCompleteness` is `.incomplete` (D-17), analysis consumers MAY process the captured portion **only** with explicit coverage metadata attached to every output (which span was analyzed; what's known-missing — D-07: unavailable, never fabricated). Consumers that cannot honestly scope partial coverage MUST skip entirely — today that is `SpeakerDiarizationEngine` (its blanket skip stays until coverage-aware diarization exists). Rationale: an instrument that stays silent about ~82%-valid signal withholds available measurement; a measurement presented without its validity context is the failure mode SaMD discipline forbids. Supersedes R5.4's blanket skip as the platform principle; R5.4's behavior remains correct for diarization specifically under this rule.
- **D-19 (2026-10-24): Measurement semantics for captured-but-discontinuous audio (director-settled at U4a-1 verification, per proposal R2 §6, ChatGPT-reviewed).** A saved file whose session is `.incomplete` — or whose completeness is unknown-legacy (`nil`) — is treated as *potentially* spliced: the completeness enum alone never establishes a join (patterns are enumerated, default `.unknownPattern`, narrowed only by named evidence). Join localization uses two candidate-grade evidence sources, always reported separately, never fused: lifecycle inference (an **interval** under stated assumptions — recognition-restart timestamps are a weak upper-bound witness, never capture-resumption times) and signal candidates (near-digital-silence runs, noise-floor steps; false positives possible, and a splice can be seamless). Every location a join plausibly occupies is excluded with a guard; when evidence cannot bound it, the whole file becomes one unresolved region: join-sensitive measurements abstain (`insideUnresolvedRegion`), frame-local measurements remain reported with flags, and no wall-clock mapping or cross-span trend statement is made for anything but `.complete`-with-no-losses sources. Abstention beats fabrication even when little audio remains; no safe spans are manufactured to satisfy acceptance criteria. `missingAudioIntervals` entries are joins at a known file offset with a known missing duration — NOT subtractable spans (verified against `recordLoss`: their `end` counts frames that were never written). Unknown-legacy completeness is unknown provenance, not confirmed complete. Production prerequisite for join-sensitive measurements (U4): prospective `CaptureDiscontinuityEvent` records — writer-owned sample offsets, monotonic capture times on both sides of the gap, reason, uncertainty, clock identity, multiple events per session — set at recovery time when the offset is actually known; recognizer callback timestamps are not an acceptable offset source. First applied and artifact-verified: U4a-1 (xcresult runs 2026-10-24 17:42/17:45; U6b session domain split into 7 spans / 95.9 s analyzable; legacy session abstained 648 join-sensitive measurements while reporting 432 frame-local values).
- **D-20 (2026-10-25): Bounded SpeechAnalyzer fixture spike approved — scope-ruling change; spike ≠ migration.** Owner decision on the director's recommendation, supported by the U4a-2 ChatGPT review (Q4(i) in `PROPOSALS/U4a-2-chatgpt-review-brief.md`): before U5 is sized, run a small, time-boxed, test-only comparison of Apple's newer `SpeechAnalyzer`/`SpeechTranscriber` API (present in the installed Xcode 27 SDK, director-verified) against the current `SFSpeechRecognizer` path on the existing fixtures. Rationale: U5 as queued builds reconciliation around E8's observed replacement/loss behavior; the newer API's audio-time-based results and explicit volatile/final semantics could change U5's shape — sizing before the spike risks building for the wrong engine. Design bullets (from the review, binding on the spike proposal): reproduce E8 with the current API as comparator; run the same saved PCM through SpeechAnalyzer (finalized results first, then volatile handling); score against a reference transcript — omissions, substitutions, insertions, duplicates, retained earlier content (raw word count is not fidelity); check file-relative timing, internal pauses, long recordings, finalization, cancellation, interruption/recovery; verify device/locale support, installed assets, offline operation after provisioning, resource cost. **The spike does NOT authorize migration** (SDK presence is not authorization), and it must not assume SpeechAnalyzer supplies replacement voice analytics. Migration remains out of scope pending the spike's results and a separate owner decision.
- **D-21 (2026-10-25): Channel-A validity-evidence units adopted, ordered.** Owner decision on the director's recommendation, supported by the U4a-2 ChatGPT review (Q4(ii)): **V1 first — estimator agreement**: Channel-A F0 vs independently configured Praat/YIN on matched voiced frames across pitch ranges, noise and phonation conditions, with Bland–Altman analysis; must report voicing disagreements, missing estimates, octave errors, bias and limits of agreement, and account for frame clustering within recordings/people (thousands of frames ≠ thousands of independent observations); agreement between estimators is evidence of agreement, not ground-truth accuracy. **V2 second — within-person repeatability/MDC**, after the measurement definition stabilizes: separate repeated analysis of identical audio from repeated recordings; predefine the session-level measure, recording conditions and interval the MDC applies to; a single-person result supports that person and protocol only. Both proceed alongside D-20's spike and never block a transcript-only U5 prototype, but they **must precede any claim that a measured behavioral change exceeds measurement error** (product priority: transcription infrastructure supports audio-grounded measurement; it does not define its validity).
