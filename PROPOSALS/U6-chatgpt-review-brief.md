## Claude's proposed mechanisms (Hermes-verified against the code; line numbers confirmed)
- **(a):** `handleInterruption` (SpeechRecognitionManager.swift:768–811) is the only restart path; it runs only on `.ended` and only if the OS sets the `.shouldResume` bit → `beginListeningSegment()`. `.began` does `audioEngine.stop()` + `removeTap`, sets `isRecording=false`. There is zero `scenePhase`/foreground-transition handling anywhere in the app. The status text "Paused by an interruption. Tap Start to resume." (line 805) is misleading: the Start button routes to `startCapture()` → a NEW reflection, not a resume.
- **(b):** `missingAudioIntervals`/`isReliable` (writer, lines 270–271) are mutated ONLY in `recordLoss(frameCount:)` (334–339), which fires only on write/buffer failures. During an interruption the tap simply stops delivering buffers — no writes, no losses recorded — so the writer cannot know a real-time gap occurred.
- **(c):** `beginListeningSegment()` creates the `AudioFileWriter` (line 613 — file+header created immediately) and installs the tap BEFORE `engine.prepare()/start()`; if start throws, the catch (647–650) only sets a status message and calls `stop()`, and `stop()` (813–835) never touches `audioWriter`. Next reflection's `start()` does a bare `audioWriter = nil` (519) with no flush/finalize → orphaned header-only file. Also: the store's `activeSession.state == .recording` and the manager's `isRecording` are independent booleans with no failure link-back, so a failed resume can leave the session stuck in `.recording` forever.

## Claude's proposed fix (full proposal summarized)
1. A shared **idempotent resume entry point**, triggered from BOTH `handleInterruption(.ended)` (existing path) and a NEW `scenePhase`-becomes-active backstop in the SwiftUI screens; guarded by `wasRecordingBeforeInterruption == true && !isRecording`.
2. A new writer method **`recordExternalGap(fromAudioSeconds:toAudioSeconds:)`**, called at interruption-began and at resume (or failure), using the writer's existing audio-seconds math, flipping `isReliable=false` and appending to `missingAudioIntervals`. Reuses existing D-09 fields; NO new model fields (Claude explicitly rejected adding an `interruptionOccurred` marker as duplicative).
3. **Guaranteed finalization**: every path that replaces/discards `audioWriter` (the bare `= nil` in `start()`, the `beginListeningSegment` failure catch) flushes/finalizes via the existing completion path first.
4. A new `@MainActor` **failure callback** (same shape as existing `onTranscript`/`onSilenceGap` closures) invoked when resume fails for good; `ReflectionSessionStore` wires it to finalize `activeSession` through the same completion path `stopAndObserve()` already uses (session transitions to `.completed` honestly instead of staying stuck).
5. Logic-level simulator unit tests: gap recording correctness, resume idempotence/no-op cases, writer-flush-before-discard. Device smoke-test re-run (rollover + chained interruption) is U6's exit criterion, user-performed, with forensic verification afterward.

ChatGPT Reply:
1. **Q1 — Auto-end only after bounded recovery fails.** A single failed restart should not automatically end a reflection. Allow a small, bounded recovery attempt while the session is still eligible to resume; never retry indefinitely or after an explicit user stop. If recovery fails, finalize the captured material and clearly tell the user recording ended. A manual “Retry recording” action is reasonable only if it resumes the same reflection correctly. The existing Start action is not that affordance. Define “fails for good” before implementation.

2. **Q2 — No, the dual-trigger guard is insufficient.** `wasRecordingBeforeInterruption && !isRecording` does not distinguish paused, starting, failed, stopping, or already finished. Both triggers could pass while a restart is underway; a delayed trigger could revive an obsolete session. Require:
   
   - One serialized lifecycle owner with an explicit resume-in-progress state.
   - A session/generation identity that invalidates stale notifications, retries, and completions.
   - Recording intent distinct from whether the engine is currently running; explicit Stop must revoke that intent immediately.
   - One recovery path shared with rollover and D-06 guards, with defined precedence.

   Foreground activation should request reconciliation of an interrupted session, not independently start capture. Chained interruptions must not overwrite the original pending gap or create overlapping restarts.

3. **Q3 — The proposed audio-seconds gap is not honest under D-05.** If file time advances only on successful writes, an interruption has no positive-duration interval in that timeline. Appending elapsed real time as audio seconds would mislocate subsequent audio and could break D-08 matching. A zero-duration boundary identifies a discontinuity but cannot represent how much capture was missed—and downstream consumers might discard it.

   Record elapsed capture gaps in a monotonic, session-relative timeline, with a separate file-offset boundary or mapping if the existing schema supports it. First audit every consumer of `missingAudioIntervals`. **Do not silently change that field’s coordinate system or mix coordinate systems within it.** If existing fields cannot represent the distinction, the “no model field changes” constraint prevents a complete solution. Narrow U6 to an honest reliability flag and explicitly defer duration/mapping, or authorize a minimal schema change. Do not invent audio intervals to satisfy the constraint.

4. **Q4 — Close it, then remove the zero-write file from usable artifacts.** A valid empty file still contains no captured audio. Close/finalize the writer to release resources, then delete the file if it has zero successfully written frames and no diagnostic retention requirement. Persist the failure through whatever existing mechanism actually supports it; do not publish the file as a successful segment. Preserve earlier nonempty segments. Verify frame counts rather than using “4096 bytes” as the deletion rule, and handle cleanup failure explicitly.

5. **Q5 — The callback is a reasonable minimal fix, with stronger ownership rules.** A broad state consolidation can wait. U6 still needs a precise contract: the store owns session intent/state; the manager reports capture transitions and terminal failure for a particular session identity. The store must ignore stale callbacks and finalize exactly once. Route user stop and terminal failure through shared finalization mechanics, while preserving their different user-visible explanations. A callback that simply completes whichever session is currently active introduces a new race.

6. **Q6 — Several acceptance requirements are missing.**
   
   - **Separate capture health from transcript health.** Four persisted words prove poor transcription continuity, not by themselves missing audio. Verify the actual audio artifacts across the affected period. A resumed engine can coexist with a dead recognition task; U6 needs evidence that both recover.
   - **Close gaps on actual capture recovery**, preferably first accepted audio, rather than merely a successful restart call. Close outstanding gaps at terminal stop/failure too.
   - **Handle absent notifications.** Recovery and reliability cannot depend exclusively on receiving `.began`. Reconcile engine, tap, and recognition state on relevant lifecycle events. If the outage onset is unknown, report uncertainty instead of fabricating a precise start time. Any silence-based health check must distinguish absent buffers from valid quiet audio.
   - **Define writer ownership across segments.** Finalize-on-replacement must preserve ordering, pending writes, artifact association, and exactly-once completion. If finalization is asynchronous, initiating it does not establish “flush before discard.”
   - **Fix the misleading copy in U6.** It directly misdirects recovery and is within scope.
   - **Expand tests before the device run.** Cover duplicate/reordered triggers, chained interruptions, Stop during restart, stale callbacks after a new reflection starts, restart failures at each resource-acquisition step, zero-write cleanup, partial-write preservation, and rollover/recovery overlap. Assert persisted state and artifact contents, not merely callback counts.
   - **Make the device exit criterion measurable.** Use recognizable speech before and after interruption; verify resumed audio and transcription, correct reliability metadata, completed session state, and no orphaned writers. Keep accumulation accuracy outside U6.

7. **Verdict — Approve with changes; do not implement the proposal as written.** The scope is justified, and shared recovery, guaranteed cleanup, and terminal-failure propagation are sound directions. The two major defects in the plan are the insufficient restart guard and the undefined gap coordinate system. Resolve both in a revised design before changing production lifecycle code. If the existing schema cannot represent interruption gaps honestly, explicitly revise the schema constraint or narrow the promised outcome. U6 cannot claim reliability integrity while persisting misleading intervals.
